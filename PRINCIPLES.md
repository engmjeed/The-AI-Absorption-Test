# The Absorption Principles
## مبادئ الابتلاع

These principles extend **The AI Absorption Test** from diagnosis into product redesign.

> The test asks: **What will AI absorb?**
>
> The principles ask: **What should the product become afterward?**

Canonical repository: https://github.com/engmjeed/ai-product-survival-test

---

## 1. Value Migration — انتقال القيمة

When AI absorbs a feature, value does not always disappear. It often moves.

Ask:
- If the interface or core feature becomes free and native, where does customer value move?
- Does it move to proprietary data, execution, trust, distribution, identity, compliance, transactions, or accumulated history?
- Can the product own that destination?

**Rule:** Do not defend a shrinking layer. Follow the value to the layer that becomes more important.

## 2. Own the Source, Not the Interface — امتلك المصدر لا الواجهة

Interfaces are easy for AI to replace. Unique state and authoritative sources are harder.

Prefer owning proprietary records, verified identity, permissions, transaction history, reputation, operational state, execution integrations, authoritative domain data, and network relationships.

Ask:

> If AI becomes the user's interface, does it still need my product as a source, system, permission layer, or execution layer?

**Rule:** Being the best screen is fragile. Being the source of truth, action, or permission is stronger.

## 3. Reality Anchor — مرساة الواقع

A general model can generate text, plans, summaries, code, and recommendations. It cannot invent legitimate real-world state.

Reality anchors include payments, contracts, approvals, verified people or organizations, device state, inventory, permissions, earned reputation, execution outcomes, audit trails, and operational records.

Ask:

> What does this product know, own, verify, or change in the real world that a model cannot generate by itself?

**Rule:** The closer value is tied to real state and real consequences, the harder it is to absorb.

## 4. Episodic to Workflow — من حدث إلى سير عمل

One-shot tools are easier to replace than products embedded in recurring work.

Look for a loop such as:

**Create → Execute → Observe → Decide → Update → Repeat**

Ask:
- Is this a one-time task or a recurring process?
- What makes users return after the first successful output?
- Can the product capture the result of each cycle and improve the next one?

**Rule:** Move from generating an answer to participating in the full operating loop.

## 5. AI as a Channel — الذكاء الاصطناعي كقناة

Do not treat AI only as a competitor. It can also become a distribution layer.

Ask:
- If assistants and agents become the primary interface, can they discover, cite, call, or transact through this product?
- Can the product expose structured, authoritative, machine-readable data or actions?
- Does more AI usage create more demand or referrals for the product?

**Rule:** The strongest position may be to become infrastructure that AI uses, not an interface that competes with AI.

## 6. Time to Moat — الزمن حتى ظهور الحاجز

A future moat is not a current moat.

Ask:
- What is the first defensible asset the product can create?
- How long does it take to become meaningful?
- What must be true for the product to survive until then?
- Can a competitor copy the product before that asset compounds?

**Rule:** Score what exists today. Treat future defensibility as a hypothesis that must be validated.

## 7. Absorbable Shell / Defensible Core — القشرة القابلة للابتلاع والنواة الدفاعية

Split the product into two layers.

### Absorbable shell
Typical examples: UI, prompts, generic search, summarization, generation, classification, basic agents, and generic automation.

### Defensible core
Typical examples: proprietary state, real-world events, identity and permissions, trusted records, workflow ownership, transaction history, network effects, distribution, and execution authority.

Ask:

> If every generic AI capability became free tomorrow, what part of this product would still deserve to exist?

**Rule:** Let AI commoditize the shell. Invest in the core.

---

# Survival Design

After every Full evaluation, produce a **Survival Design** with:

1. Absorbable shell
2. Defensible core
3. Value migration
4. Reality anchor
5. Workflow evolution
6. AI distribution path
7. Time to moat
8. Redesign recommendation
9. Build decision

The Survival Design does **not** receive a second numerical score. The 100-point score diagnoses the current product; the Survival Design explains how to improve it.
